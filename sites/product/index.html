00 / THE PREMISE

One less layer between you and the thing you’re making.

Development already has enough moving parts. Your naming layer shouldn’t add more.

  • No per-project /etc/hosts edits
  • No certificate files to choreograph
  • No Caddy required in the runtime path

01 / HOW IT WORKS

Your machine is the host.
Your app stays where it is.

Run the daemon on the machine with your browser. Each dev environment registers over a single outbound connection.

05 / CLEAR BOUNDARIES

Local means local.

No account system. No central service. No telemetry, usage reporting, or name reporting.

01

Root key stays home

Your CA private key remains on the host, never in a dev environment.

02

Dashboard on loopback

Administrative actions need a per-run token. The edge never proxies the dashboard.

03

Remote targets constrained

Remote leaves can target only their own address unless you explicitly opt in.

04

Plainly documented

Registration uses plain TCP. Use a trusted network or encrypted transport; never expose :7737 publicly.

  1. 01

    Prepare the host

    Create the local CA, configure the resolver, and start the daemon.

  2. 02

    Name your project

    Run the command where your app lives. Add your dev command after -- to tie their lifetimes together. A new remote environment asks for one approval on the host.

  3. 03

    Open the address

    Your browser gets a stable, trusted URL. Keep the command running; stop it to release the name.
